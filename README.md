双击 `index.html` 即可离线打开。用键盘、触屏或红外感知台操控角色，在十四个随机地面场景中跑酷，并可从未来城进入太空支线。

## 滑动变道 UI 设计稿

`swipe-control.html` 是一份独立的滑动控制设计稿与可交互原型，打开即可体验：

- **原理**：在屏幕上按下并左右滑动，`dx = clientX − startX`；`|dx| ≥ 35`（CSS px，与 `runner.js` 一致）立即变道，一次手势只切一条道，抬手后重新计数。
- **两端一致**：手机手指与电脑鼠标走同一套 Pointer Events、同一段判定代码，阈值固定为 CSS px，不做 `vw` 换算。
- **交互**：在「滑动区」或沙盘画面上左右滑动即可模拟，`←` / `→` 为降级操作。
- **内容**：三段式判定、实时读数、手机/电脑一致性对照、HUD 布局稿、状态与反馈规范。

`hand-control.html` 为旧地址，已自动跳转到新页面。

### 骨骼数据如何接入（已实现，不改感知台任何文件）

红外感知台每帧把 33 点骨骼写入：

```
<安装目录>/files/outputs/local_<pid>/latest_keypoints.json
```

`ms01_bridge.py` 自动发现最新的这个文件，取 `people[0].pose33`，按 MediaPipe 33 → COCO-17 映射后 POST 到 `http://127.0.0.1:8766/pose`，再由 `ws_server.py` 广播给网页。全程只读感知台的输出文件，**不修改它的代码或配置**。

点位与动作对应：

| 动作 | 判定 |
|---|---|
| 左/右变道 | 肩中点与髋中点的横向偏移 / 肩宽 |
| 跳跃 | 双肩中点相对基线上升超过 0.045 |
| 下蹲 | 双肩中点相对基线下降超过 0.032 |

启动顺序：

1. 打开红外感知台，确认处于“本机识别”运行状态，画面里有人（`live_stats.json` 的 `running` 为 true，`latest_keypoints.json` 的 `people` 非空）。
2. 双击桌面“姿态跑酷”，它会依次启动 WebSocket 服务、骨骼文件桥接、打开游戏页面。
3. 站到镜头前做动作。

排查：

| 现象 | 处理 |
|---|---|
| 页面绿点已连但人不动 | 看“MS01-骨骼桥接”窗口，若一直提示“画面中暂未检测到人体”，是感知台没识别到人 |
| 左右相反 | 参数面板勾“反转倾斜方向”，或改用 `ms01_bridge.py --mirror` |
| 动作触发不灵敏 | 调小倾斜阈值/稳定帧数，或加大动作幅度 |
| 想确认桥接是否收到数据 | `ms01_bridge.py --verbose` 会打印“已接入骨骼：people=N” |

## 启动顺序

1. **启动转发服务**（在项目目录打开终端）：
   ```bash
   python ws_server.py
   ```
   正常应看到：`服务已启动 ws://127.0.0.1:8765/`。

2. **打开游戏**：双击 `index.html`。页面右上角显示“姿态设备已连接”即表示 WebSocket 已连接。

3. **点击“开始奔跑”**，先用键盘 A / D / 空格确认游戏本体正常。

4. **接入骨骼模组**：让采集模组以 `?role=pose` 连接同一个服务：
   ```
   ws://127.0.0.1:8765/?role=pose
   ```
   模组把识别结果以 JSON 发给服务，服务自动广播给所有游戏页面。

### 难度和追逐

| 难度 | 地面起跑速度 / 上限 | 基准出障碍间隔倍率 |
|---|---|---|
| 普通 | 24 / 54 | 100% |
| 困难 | 34 / 74 | 66% |
| 魔鬼 | 42 / 88 | 52% |

障碍可能并排占两道或三道。三道都有障碍时，至少一道可以用普通跳跃或下蹲通过。困难和魔鬼更常出现组合与高难障碍，排程会给相邻组合留出反应时间。开局在角色馆预览和选择角色，已选角色与难度会保存在本机，各难度单独保存最高分。

第一次碰到凸出树根、松脱桥索等低矮绊脚物，角色会踉跄减速，光头强会从后方追近。你使用光头强时，由熊二追赶。接下来 8 秒再绊一次就会被抓住。安全跑完这段时间会拉开距离。跳过或绕开绊脚物可避免触发，已有的护盾会先吸收碰撞。致命碰撞和连续绊脚都通过追上、抓住的动画进入结算。

### 拾取与动作

- 每枚金币加 2 分，也计入本机的金币余额。每串路线最多 12 枚，沿安全跑道铺开；全断桥的金币会沿跳跃路线抬升。
- 熊二和熊大可以直接选用。角色馆可预览并解锁光头强（60）、萝卜头（90）、蹦蹦（120）、毛毛（145）、吉吉（180）、翠花（215）、老鳄（250）和铁掌大师（300）。余额和解锁记录保存在当前浏览器。
- 在 5.4 秒内连续跳过、钻过或变道避开障碍可获得连招加分，撞击或超时中断连招。整排组合只计一次，结算会显示本局最佳连招。
- 护盾来自独立的蜂蜜罐。地面安全补给点在未持有护盾时有 3.5% 的基础机会刷新蜂蜜罐，每关最多刷新一次。拾取后，角色头部出现保护罩，挡下一次碰撞后破裂。太空入场自动补给一次护盾。
- 弹跳鞋在安全补给点的基础刷新机会为 14%，每关最多刷新一次。拾取后持续 30 秒，跳跃高度超过普通跳跃的两倍。它能越过篝火、竹水轮、尖礁、蜂群、老虎、石像、冰岩、防风栅、悬浮列车、等离子墙、陨石、太阳翼和推进喷流。漩涡仍然要变道。
- 拾到火箭背包后进入自动升空阶段。飞行期间可以左右移动，暂停后可继续飞行。
- 按 P 或 Esc 可暂停。「设置」可调变道与触屏滑动灵敏度、音量和姿态阈值，也可开关教程、障碍补给提示及碰撞和转场特效。设置会保存在本机。

## WebSocket 协议

- 地址：`ws://127.0.0.1:8765/?role=game`（网页）/ `?role=pose`（骨骼模组）
- 方向：pose → 服务端 → 所有 game 客户端
- 格式：JSON 文本

方案 A（模组侧识别动作，推荐）：
```json
{"action": "left", "confidence": 0.86}
```
`action` 取值：`left` / `right` / `jump` / `duck` / `idle`。`jump` 是脉冲信号（触发一次后需再次置为 idle 才能再触发），`left/right/duck` 是持续信号（页面按“稳定帧数”做边沿触发；`duck` 松开即恢复站立）。

方案 B（网页侧用关键点判定）：
```json
{"keypoints": [[x,y,conf], ...17个点...], "width": 640, "height": 480, "confidence": 0.9}
```
关键点索引采用 **COCO-17**：5 左肩、6 右肩、11 左髋、12 右髋，坐标系 x 向右、y 向下；归一化 `[0,1]` 或像素坐标均可（像素坐标需带 `width`/`height`）。网页会低通滤波后判定倾斜方向，并用双肩高度变化判定下蹲起跳。

无效数据（action 不在枚举内、置信度低于阈值、JSON 解析失败）会被直接丢弃。

## 常见问题排查

| 现象 | 排查点 |
|---|---|
| 右上角一直显示“已断开” | 服务没启动；端口被占用；页面地址里的 `ws=` 参数写错 |
| 状态灯绿了但骨骼没反应 | 用 `--demo` 测试；确认模组连接时带了 `?role=pose`；确认 JSON 里 action 拼写正确 |
| 动作有但角色抽风式来回变道 | 调大“稳定帧数”和“倾斜阈值”；确认骨骼端输出的是持续信号而非单帧抖动 |
| 一直跳或跳不起来 | 调大“跳跃冷却”；降低“置信度阈值”前先确认骨骼端输出是否合理；方案 B 需要双肩相对基线明显上升 |
| 蹲不下去 / 一直蹲着 | 方案 A 需先发 `{"action":"duck"}` 再发 `idle` 恢复；方案 B 检查双肩高度是否变化足够大 |
| 如何通过半断桥 | 换到有桥面的一侧，或跳过缺口 |
| 看不到大象 | 大象只在森林段生成，可用 `?startzone=0` 确认；其他场景不会生成大象 |
| 左右方向相反 | 勾选参数面板的“反转倾斜方向” |
| 页面黑屏 / 角色不显示 | 检查资源子目录是否齐全，确认浏览器支持 WebGL 并开启硬件加速 |
